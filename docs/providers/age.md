# age vault

age provides built-in encryption without installing pass or GPG.

## Create a vault

```sh
lazypass vault init --provider age --name personal
lazypass vault
```

Choose and confirm a passphrase when prompted. Initialization adds the vault to
your configuration. Vault names must be unique and use lowercase letters,
numbers, or hyphens.

Your identity is unlocked when you first read, copy, or edit a value, and stays
unlocked until you exit the app. Browsing and adding values do not require it.
Entry names and folder names remain visible on disk.

## Storage

For the name `personal`, default locations are:

- Vault: `~/.local/share/lazypass/vault-personal`
- Encrypted identity: `~/.config/lazypass/identity-personal.age`

The default name `age` uses `vault` and `identity.age` instead. XDG data and
configuration directories are respected. Set custom paths during initialization:

```sh
lazypass vault init --provider age --name personal \
  --store-dir /path/to/vault \
  --identity-file /path/to/identity.age
```

Keep the private identity outside the vault directory.

## Use an existing identity

Supply its public X25519 recipient and the path to your identity file:

```sh
lazypass vault init --provider age --name personal \
  --recipient age1... --identity-file /path/to/identity.txt
```

Existing unencrypted identity files are supported. New identities generated by
lazypass are always passphrase-protected.

## Backup and recovery

Back up the vault directory and encrypted identity, and keep your passphrase
recoverable separately. You need both the identity and its passphrase to restore
access. The public recipient in `vault.json` cannot recover your passwords.

To restore, copy the vault and identity to their new locations and update their
paths in your configuration:

```yaml
vaults:
  - name: personal
    provider: age
    storeDir: /path/to/restored/vault
    identityFile: /path/to/restored/identity.age
```

Automatic sync, key rotation, and migration from other providers are not yet
available.
